# Plan: Product vision & design system

[Section context](README.md) · [Portfolio overview](../../README.md)

## Intended outcome

Make a privately operated collection easy to explore from the Apple device already in use.

## Work sequence

1. Maintain one destination and capability inventory across all four editions.
2. Audit contrast, text scaling, focus indication and empty/error/loading states.
3. Refresh publication captures after accepted UI changes; retain their build and capture method.

## Acceptance criteria

- [ ] Each visible destination has an owner, implementation status and return path.
- [ ] A first-time reader can tell a current feature from a proposed one.
- [ ] Keyboard, VoiceOver and remote focus checks are recorded per platform.

## Evidence and boundaries

Acceptance boxes are requirements for the next complete validation pass, not claims that every item is currently untested. See the [recorded evidence](../12-release/EVIDENCE.md) for completed checkpoints and remaining gaps. Provider and platform dependencies are described in the [architecture](../10-home-lab/README.md) and [identity plan](../11-identity/PLAN.md).
